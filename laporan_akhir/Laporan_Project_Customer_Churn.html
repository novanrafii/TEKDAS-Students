Ringkasan Eksekutif

Proyek ini membangun alur analitik untuk retensi pelanggan e-commerce: data CSV divalidasi dan disiapkan, metrik Business Intelligence (BI) ditampilkan, Random Forest memprediksi kemungkinan churn, dan Large Language Model (LLM) lokal menyusun saran tindakan berdasarkan bukti yang dibatasi. Target adalah churned pada 8.000 pelanggan; evaluasi memakai test set terstratifikasi berukuran 1.600 pelanggan.

ROC-AUC0,733

F1 churn0,387
Churn test set8,94%

Pada threshold 0,50, model mendeteksi 69 dari 143 pelanggan yang benar-benar churn, dengan 145 false positive. Accuracy 86,31% tidak melampaui baseline mayoritas 91,06%; accuracy saja menyesatkan pada kelas tidak seimbang. Nilai proyek terletak pada pemeringkatan risiko dan pengaturan threshold, bukan pada klaim bahwa seluruh churn dapat diprediksi tepat.

Temuan kualitas data. monthly_revenue.csv merepresentasikan revenue order Delivered, sehingga return_rate selalu nol. Analisis return harus menggunakan orders.csv.

1. Pendahuluan

Masalah dan tujuan

Churn pelanggan mengurangi pendapatan berulang dan membuat upaya retensi terlambat bila hanya mengandalkan pengamatan manual. Proyek ini menyediakan aplikasi pembelajaran yang menautkan fakta transaksi, ringkasan BI, skor prediktif, dan narasi tindakan. Stakeholder utamanya adalah manajer retensi yang perlu memilih pelanggan untuk ditindaklanjuti serta alasan yang dapat diperiksa.

Pertanyaan rekayasa

  • RQ1: Seberapa baik Random Forest membedakan pelanggan churn dan tidak churn?
  • RQ2: Bagaimana threshold mengubah precision, recall, false positive, dan false negative?
  • RQ3: Bagaimana LLM diberi evidence agar tidak mengarang fakta atau menganggap prediksi sebagai sebab?

Kontribusi

Kontribusi artefak ini adalah implementasi CSV → BI → ML → LLM → Streamlit untuk churn. Track laporan adalah REPRODUCE: pipeline, data, dan output diperiksa dari implementasi referensi yang tersedia; tidak ada klaim kebaruan algoritmik.

3. Metode dan Arsitektur

Gambar 1. Arsitektur end-to-end. LLM tidak menggantikan model klasifikasi.

Persiapan fitur

Data dibagi stratified menjadi 6.400 data latih dan 1.600 data uji (test_size=0.20, random_state=42). Tujuh fitur kategorikal meliputi negara, gender, tier keanggotaan, kategori/perangkat/metode pembayaran pilihan, serta channel akuisisi. Empat belas fitur numerik mencakup perilaku pembelian dan fitur rekayasa customer_tenure_days, orders_per_year, reviews_per_order, dan returns_per_order. Total fitur sebelum one-hot encoding adalah 21.

Model dan metrik

Pipeline memakai median imputation (numerik), most-frequent imputation dan OneHotEncoder (kategorikal), kemudian RandomForestClassifier dengan 350 pohon, min_samples_leaf=3, class_weight=balanced, dan seed 42. Metrik: precision, recall, F1, ROC-AUC, dan confusion matrix. Precision menilai alert yang benar, recall menilai churn terdeteksi, dan ROC-AUC menilai kemampuan peringkat lintas threshold.

6. Aplikasi dan Integrasi LLM

Dashboard Streamlit memiliki empat tab: Kaggle Data untuk inspeksi tabel; BI untuk trend revenue dan kategori; Machine Learning untuk peluang churn dan threshold; dan LLM Analyst untuk rencana retensi. Pengguna memilih customer_id, lalu aplikasi membangun fitur dengan fungsi yang sama seperti pelatihan sebelum memanggil predict_proba.

Grounding dan batasan prompt

Prompt Ollama llama3.2 memuat profil pelanggan, probabilitas churn, hingga lima order terbaru, dan delapan feature importance global. Instruksi mewajibkan LLM memakai fakta yang diberikan, menyatakan bahwa skor bukan sebab, tidak mengarang motif/keluhan/pendapatan, serta memberi dua observasi, dua aksi proporsional, dan satu peringatan batasan.

7. Etika, Keterbatasan, dan Kesimpulan

Penggunaan bertanggung jawab

  • Privasi: customer ID dan atribut pelanggan harus dibatasi aksesnya.
  • Fairness: country dan gender dapat membawa risiko disparitas; perlu evaluasi per kelompok.
  • Automation bias: skor dan teks LLM harus mendukung, bukan menggantikan, keputusan staf.
  • LLM: grounding mengurangi tetapi tidak menghilangkan risiko halusinasi; output harus diaudit terhadap prompt dan data sumber.
  • Keamanan: prompt, log, model lokal, dan data retensi memerlukan pengendalian akses dan kebijakan penghapusan.

Keterbatasan

  • Provenance dan lisensi sumber Kaggle tidak tercatat dalam artefak.
  • Label historis bukan bukti mekanisme kausal; periode observasi perlu diperjelas.
  • Hanya satu hold-out split; belum ada validasi silang, uji temporal, kalibrasi probabilitas, atau monitoring drift.
  • Baseline mayoritas mengungguli model pada accuracy; performa churn masih moderat.
  • Feature importance global tidak menjelaskan satu pelanggan secara kausal.
  • LLM belum diuji kuantitatif untuk konsistensi evidence, keamanan, atau kegunaan pengguna nyata.

Kesimpulan

Pipeline berhasil menghubungkan data e-commerce, BI, prediksi churn, dan saran bahasa alami dalam satu dashboard. Pada 1.600 data uji, Random Forest mencapai ROC-AUC 0,733, precision churn 0,322, recall 0,483, dan F1 0,387 pada threshold 0,50. Threshold lebih rendah meningkatkan deteksi churn (recall 0,601 pada 0,30) dengan kenaikan false positive. LLM dirancang sebagai lapisan komunikasi berbasis evidence, bukan sumber fakta atau penyebab churn. Sebelum penggunaan nyata, proyek memerlukan dokumentasi data, evaluasi fairness/kalibrasi/temporal, dan evaluasi LLM terstruktur.
